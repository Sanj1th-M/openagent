# CodeQL Remediation Audit

**Repository:** `Sanj1th-M/openagent`  
**Audited branch and commit:** `main`, `c9e2df5c06482dc166094a5172c67a02fe640b85`  
**Audit date:** 2026-11-23  
**Alert source:** authenticated GitHub Code scanning page, filtered to `is:open branch:main`

## Initial findings

The dashboard showed **24 open alerts**: **21 High** and **3 Medium**. The findings cover path injection, provider URL classification, reflected script output, redirect construction, upload error disclosure, credential logging/storage, and a temporary port availability probe. Alert titles alone were not treated as proof: affected source and the CodeQL path for the upload path finding were inspected.

The path-injection trace starts at the `filename` route parameter in `dashboard/server.py:1153`, passes through separator removal at line 1158, and reaches path construction and file access at lines 1159–1162. Removing separators was insufficient: `../secret` becomes `..secret` in some cases, while a filename exactly equal to `..` can still escape the uploads directory. The remediation canonicalizes the candidate, checks containment with `relative_to`, rejects invalid basenames, and blocks symlink targets outside the upload root.

## Changes made

- `dashboard/server.py`: confined upload downloads, safely encoded inline script values, generic upload errors, and a locally pinned HTTPS redirect destination.
- `providers/llm_openai.py`: exact parsed-host checks for Gemini and MiniMax provider-specific behavior.
- `core/gemini.py`, `main.py`, `core/audio_devices.py`, `actions/dev_agent.py`: removed raw exception, device, model, or credential-like values from affected logs; added common credential redaction to the coding-agent logger.
- `memory/config_manager.py`: private POSIX config directory/file modes and restrictive same-directory temporary writes.
- `tests/test_codeql_remediation.py`: regression coverage for path traversal, symlink escape, HTML/script encoding, URL host spoofing, redirect authority, upload exception disclosure, config permissions, and log redaction.
- `requirements.txt`, `actions/file_processor.py`, and `core/cloud.py`: removed the vulnerable PyPDF2 fallback and retained the existing `pypdf` fallback at version 3.9.0 or newer. This followed a dependency audit finding for crafted PDFs that could cause an infinite loop; the upstream advisory lists PyPDF2 3.0.1 as affected and pypdf 3.9.0 as patched ([GHSA-4vvm-4w3v-6mr8](https://github.com/advisories/GHSA-4vvm-4w3v-6mr8)).
- `docs/SECURITY.md`, `docs/CONFIGURATION.md`: documented the updated path, permission, and storage behavior.
